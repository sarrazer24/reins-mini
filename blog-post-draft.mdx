## The claim

REINS (Ding et al., EMNLP 2026) steers a language model through sparse-autoencoder features. For each prompt it suppresses the features that support the harmful continuation (Harm-Inhibit) and adds a fixed set of refusal features on the first few generated positions (Refusal-Enhance). A gate (REINS-Gate) decides per prompt whether to steer at all. The authors build GUISE, 900 harmful requests hidden inside plausible task wrappers, each with a matched safe prompt. Their headline for Qwen3.5-2B-Base: harmful response rate falls from 88.7% to 24.8% while explicit refusals rise from 1.7% to 43.9%.

## My plan

Re-implement the method myself, run it on Qwen3.5-2B-Base with free Kaggle GPUs, and judge outputs with an open model instead of GPT-4o-mini. I use the authors' released data, SAEs and frozen refusal and gate controllers as inputs, and write the attribution, the intervention hook, the metrics and the judge pipeline myself. Deviations (smaller model, different judge, my own prompt template, harm weights fixed to 1) are listed in the repository.

## Step 1: do the paper's own numbers hold together?

The authors release code, data and frozen controllers, but no model outputs. So the only offline reference is the paper's tables. I re-derived what can be derived.

|---|---|---|
| 4B: HRR reduction of REINS vs CorrSteer-A | 39.8% | 39.82% |
| 4B: SRR ratio vs CorrSteer-A | about 2.7 times | 2.69 times |
| 2B: HRR reduction vs CorrSteer-A | 49.7% | 49.70% |
| 2B: SRR ratio vs CorrSteer-A | about 3.7 times | 3.66 times |
| Row sums of Tables 2, 6, 7, 10 | 100 | all within rounding |

All 42 arithmetic checks pass. Two things I found that the paper does not state:

- Fourteen of the 28 safety rows are not multiples of 1/300, although the evaluation split has 300 prompts. Several of them are consistent with an average over three runs of 300 (900 outputs). This is my inference, not something the paper says.
- The released data uses different field names than the paper's schema table (the harmful prompt is called a malicious prompt, the matched safe prompt is called a borderline prompt, and the crime family is called cybercrime). The released gate score is also a restricted cosine over the gate's own 256 coordinates, while the paper describes a cosine over the full feature vector. TODO: run both variants.

## Step 2: what do the metrics reward?

- A constant refusal string would score 0% harmful and 100% refusal. Only the over-refusal check on matched safe prompts separates it from real steering, and the paper reports that check only for Original, REINS and REINS-Gate.
- Empty output also scores 0% harmful. The paper itself shows this for CorrSteer-A on AdvBench (0.0% harmful with 100% collapse).
- GUISE was built by revising prompts until Qwen3.5-4B-Base fulfilled them (harmful rate 78.7% to 91.3%). Original harmful rates on that model are therefore selection-inflated, and cross-model comparisons are biased.
- The gate picks one of five gates using the sample's true category label. That is an oracle at evaluation time.
- Small-sample caveat: with 300 prompts, two runs must differ by about 7 points near 25% to be distinguishable. For the utility panels (70 MMLU-Pro and 30 GPQA questions) the minimum detectable difference is about 15 to 25 points, and every utility difference in the paper's tables sits inside that. The 2B base model scores 26.7% on GPQA against a 25% chance level, so utility preservation says little at 2B.
